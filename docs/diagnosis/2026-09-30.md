## 三份委派拷贝收进一个引擎：subagent 扩展的深化 (2026-09-30)

`~/.pi/agent/extensions/{reviewer,scout,analyst}/` 是**一个引擎抄了三份**：2,603 行里除 5 处声明式字符串
（`name` / `label` / `taskNoun` / `lead[2]` / `guidance`，即 `declarations.ts` 里一条声明的五个字段）外逐字相同，而且**零测试**。于是「改一处委派行为」要改三遍，
漏一份就表现成「某个工具比另两个少一条指引」——只在模型行为上显形，读代码看不出来。

**收成一个扩展**：`delegation/`（1,187 行，−54%）注册三个工具。pi 官方就是「一个扩展注册多个工具 +
共享状态」的用法，所以这里不是引入新机制，而是三个浅模块 → 一个深模块：

- `declarations.ts`（164 行）：**零 import**。唯一的数据 —— 3 条声明，每条恰好 5 个字段；模型能读到的
  每一个字都从这里生成。
- `engine.ts`（545 行）：只认 `d.name`/`d.label`，不认品牌名。
- `render.ts`（317 行）：`makeRenderer(d)`，TUI 渲染同样没有自有文案。
- `index.ts`（41 行）：一个 `before_agent_start`（按 `selectedTools` 注入 guidance）+ 循环注册。
- `agents.ts`（120 行）：三份逐字相同的 agent 发现代码，留一份。

关键取舍：**并行上限 `MAX_PARALLEL_TASKS = 8` / `MAX_CONCURRENCY = 4` 定义在 `declarations.ts`，
engine 反过来 import 它们** —— 工具描述里写着 "max 8, 4 concurrent"，两处各写一份必然有一处说谎。
`~/.pi/agent` 没有 package.json / node_modules，靠的是 pi 加载器支持同目录多文件 + 相对 `./x.ts` 导入。

**验证**（这个目录**没有版本控制**，备份是唯一回滚手段：`extensions-backup-20260930-092026/`）
- 三份旧文件先求成 **27/27 逐字 golden**（3 工具 × (描述 + guidance + 7 个参数描述)）。
- **旧 vs 新**：新旧各跑同一套桩，`label`/`description`/**整棵参数 schema**/guidance 注入全等；唯一差异是
  guidance 块顺序从「目录扫描序」变成「声明序」（已确认接受）。
- **真 pi 冒烟**：`PI_CODING_AGENT_DIR` 指向只含新扩展的目录，`pi --mode rpc` + `get_state` → exit 0、
  stderr 为空。该信号的有效性用负对照证明过：重复声明、或加载期抛错，pi 都会报
  "Failed to load extension" 并 exit 1。（`--tools` 里的未知工具名 pi 不校验，注册一个缺 name 的工具它
  也不报错 —— 所以「注册内容对不对」只能靠上面两条比对。）

**真机冒烟抓到、桩测试漏掉的一个 bug**：`engine.ts` 既 `import { MAX_PARALLEL_TASKS }` 又保留了原文件里
的同名 `const` → 重复声明。桩测试走 `esbuild --bundle`，而**打包器会把多模块并进一个作用域并自动重命名
冲突符号**，这类错在打包产物里天然不可见。补的检查是**非打包加载**（`node --experimental-strip-types`，
让 node 逐文件真模块求值）。教训：打包器看不见自己顺手修掉的那类错误。

`src/main/index.ts`）+ 三处指向已删目录的行号引用（130 / 740 / 765 行）。
