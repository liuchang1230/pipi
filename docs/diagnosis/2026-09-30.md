## 三份委派拷贝收进一个引擎：subagent 扩展的深化 (2026-09-30)

`~/.pi/agent/extensions/{reviewer,scout,analyst}/` 是**一个引擎抄了三份**：2,603 行里除 5 处声明式字符串
（`name` / `label` / `taskNoun` / `lead[2]` / `guidance`，即 `declarations.ts` 里一条声明的五个字段）外逐字相同，而且**零测试**。于是「改一处委派行为」要改三遍，
漏一份就表现成「某个工具比另两个少一条指引」——只在模型行为上显形，读代码看不出来。

**收成一个扩展**：`delegation/`（1,187 行，−54%）注册三个工具。pi 官方就是「一个扩展注册多个工具 +
共享状态」的用法，所以这里不是引入新机制，而是三个浅模块 → 一个深模块：

- `declarations.ts`（164 行）：**零 import**。唯一的数据 —— 3 条声明，每条恰好 5 个字段；模型能读到的
  每一个字都从这里生成。
- `engine.ts`（545 行）：只认 `d.name`/`d.label`，不认品牌名。
- `render.ts`（317 行）：`makeRenderer(d)`，TUI 渲染同样没有自有文案。
- `index.ts`（41 行）：一个 `before_agent_start`（按 `selectedTools` 注入 guidance）+ 循环注册。
- `agents.ts`（120 行）：三份逐字相同的 agent 发现代码，留一份。

关键取舍：**并行上限 `MAX_PARALLEL_TASKS = 8` / `MAX_CONCURRENCY = 4` 定义在 `declarations.ts`，
engine 反过来 import 它们** —— 工具描述里写着 "max 8, 4 concurrent"，两处各写一份必然有一处说谎。
`~/.pi/agent` 没有 package.json / node_modules，靠的是 pi 加载器支持同目录多文件 + 相对 `./x.ts` 导入。

**验证**（这个目录**没有版本控制**，备份是唯一回滚手段：`extensions-backup-20260930-092026/`）
- 三份旧文件先求成 **27/27 逐字 golden**（3 工具 × (描述 + guidance + 7 个参数描述)）。
- **旧 vs 新**：新旧各跑同一套桩，`label`/`description`/**整棵参数 schema**/guidance 注入全等；唯一差异是
  guidance 块顺序从「目录扫描序」变成「声明序」（已确认接受）。
- **真 pi 冒烟**：`PI_CODING_AGENT_DIR` 指向只含新扩展的目录，`pi --mode rpc` + `get_state` → exit 0、
  stderr 为空。该信号的有效性用负对照证明过：重复声明、或加载期抛错，pi 都会报
  "Failed to load extension" 并 exit 1。（`--tools` 里的未知工具名 pi 不校验，注册一个缺 name 的工具它
  也不报错 —— 所以「注册内容对不对」只能靠上面两条比对。）

**真机冒烟抓到、桩测试漏掉的一个 bug**：`engine.ts` 既 `import { MAX_PARALLEL_TASKS }` 又保留了原文件里
的同名 `const` → 重复声明。桩测试走 `esbuild --bundle`，而**打包器会把多模块并进一个作用域并自动重命名
冲突符号**，这类错在打包产物里天然不可见。补的检查是**非打包加载**（`node --experimental-strip-types`，
让 node 逐文件真模块求值）。教训：打包器看不见自己顺手修掉的那类错误。

**顺带修的**：原 CONTEXT.md 的 2 个裸 NUL（`grep` 一直把它当二进制 —— 见 `docs/diagnosis/2026-09-27.md`，那条只改到了
`src/main/index.ts`）+ 三处指向已删目录的行号引用（130 / 740 / 765 行）。


## 拖动侧栏分界线会选中文字、并让会话列表向上滚 (2026-09-30)

**症状**（用户报告）：鼠标放在「当前项目文件」与「项目 / 会话」的分界线上向下拖动，会话列表同时在向上
滚动，还带选中文字。顺带要求给「当前项目文件」加一个向下收起的按钮。

**根因**（三处叠在一起，全部实测出来的）：

1. **分界线的坐标换算用错了分母**：用的是整条侧栏，而两个面板划分的是「侧栏 − 表头 − 分界线」。于是手柄
   比指针跑得快，`偏移 = 表头 − 指针y × (表头+分界线)/侧栏高`，实测 17.6px（55% 向下）/ 23.2px（55% 向上）/
   27.5px（45% 向上），最大 42.6px（拖到底被 80% 夹住时）。**偏移把光标推进了会话列表**——这是后面两件事
   的前提条件，缺了它光标一直在分界线上，什么都不会被选中。
2. **两个 resizer 都没有 `user-select: none`，`onMouseDown` 也没有 `preventDefault()`**：浏览器把这次
   按下当成选区起点，随后 tracker 把选区扫过光标下的会话行（实测 399 / 446 / 542 字），并且**在会话列表
   底部边缘区内触发了选区自动滚动（autoscroll）**：`sessionScrollTop 300 → 307 / 313`。
3. 顺带一个潜伏 bug：`Number(localStorage.getItem("pipi-sidebar-split"))` 在 key 不存在时是
   `Number(null) = 0`，而 `0` 是有限数 → 绕过 `: 55` 回落 → 被夹到 20% 下限。全新配置首次启动时
   会话面板只有 118px 高（应为 ~430px），而 20% 恰好也是分界线漂移最大、最容易把光标推进会话行的状态。

**排除掉的两个嫌疑**（都花了几分钟实测，都不是原因，记下来免得下次重查）：
- *容器高度变化引起的滚动锚定*：不碰鼠标，直接改 `.sidebar-top` 的 `style.height` → `scrollTop` 300 → 300。
- *选区高亮回滚（reveal）*：拖拽中每帧 `getSelection().removeAllRanges()` → 仍然 +9。也就是说滚动来自
  autoscroll 的定时器，而不是"选中之后滚到可见"。**这条决定了修法**：只加 `user-select: none` 不够
  （几何漂移还在），只修几何也不够（选区与 autoscroll 是浏览器行为，得堵住它的起点）。

**处置**：
- 两个 resizer 加 `user-select: none` + `onMouseDown` `preventDefault()`；拖拽期间给 `<body>` 挂
  `is-row-resizing` / `is-col-resizing`，整份文档禁选中且只显示一种光标（用 `cursor: inherit` 压住逐元素的
  `pointer` / `text`，不必上 `!important`）。
- 几何换算改成**按拖动区**：按下时把 `{top, span, grabOffset}` 一次性抓成"帧"（`span` 取两个面板高度之和，
  `top` 取上面板顶边），拖动中只按这一帧反解。**帧只在按下时抓一次**：面板高度就是被拖动的量，边拖边重新
  测量等于把输出当输入反馈给拖拽。修复后手柄偏移 −2.5px（正好是"抓在 5px 手柄中心"），即手柄落在指针下。
- 「当前项目文件」加收起按钮：标签行右侧一个 ghost chevron，收起时 180° 翻转 + 分界线卸载 + 上面板 `flex:1`
  接手空间 + 列表 `display:none`，状态持久化在 `pipi-tree-collapsed`（与 `pipi-sidebar-split` 对称）。
- 纯函数搬进 `src/renderer/src/panes/sidebar-split.ts`（`clampSplit` / `readSavedSplit` / `frameFor` /
  `splitFromPointer`），node 单测 10 条，其中一条把**旧公式的偏移断言成 > 15px**——它记录的是这次修掉的机理。

**回归守卫**：`scripts/diagnose-sidebar-resizer.mjs`（CDP 真机，35 项断言）。5 个拖拽用例（两个方向 × 两个
起点 + 一个故意冲过 80% 夹取带）× 5 条断言，加全新配置默认值、收起/展开、横向分界线、渲染层异常。
每个用例先往 localStorage 写 split + `Page.reload`，所以不会继承上一个用例的布局；列表不可滚动时直接判
"fixture 不可用"而不是给绿（不滚动的空列表上"没有滚动"是废话）。

**红了才算数**：同一份脚本在修复前跑（`git stash push -- src/` 后重建）红 16 项，修复后 35 项全绿。红的那
一跑抓到的正是用户描述的那一对症状：向上拖 399 / 446 字选中 + `sessionScrollTop` +7 / +13；向下拖 220px
（20% 起点）选中 542 字但列表不滚；横向分界线也选中 24 字（同样缺 `user-select`，同类缺陷）。
"全新配置默认 55%"这条断言是看完红之后补的，它的独立证据是首次探索跑测得会话面板 118px（= 20% 下限）。

**教训**：
- 拖拽手柄的**几何**和**选区**是两个独立失败面，只修一个用户仍会看到另一个。
- 拖动中的坐标换算必须**按下时定帧**；"用整条容器当分母"是最容易写错、而且错得毫无声息的那一版。
- 渲染层测试跑在 node 环境（无 DOM），`Input.dispatchMouseEvent` 这类真输入管线在 jsdom 里根本不存在——
  凡"光标 / 选区 / 滚动位置"类症状，验证只能落在 CDP 脚本上（单测只覆盖纯几何那一半）。
