# 不做 API 中转与转售

pipi 不自建模型网关、不代售 token、不做"统一计费"、不把用户的 key 收上来再转发。默认 BYOK：用户带自己的 key，我们只做**配置便利**（一键模板：DeepSeek / 硅基流动 / Kimi / 智谱 + 自定义 OpenAI 兼容端点）。

## 为什么放到界外

- **法律与合规**：转售上游模型的推理服务在多数供应商的服务条款里需要单独授权；跨境支付、发票、退款、实名，每一样都是独立的合规面。
- **价格战**：我们没有成本优势。中转的毛利结构决定了它是"卖得越多越亏"或者"涨价即流失"。
- **资金压力**：预充值 = 我们垫资买 token，用户量一上来就是现金流问题，而它跟产品质量无关。
- **无粘性**：用户为**便宜的 token** 而来，别家便宜 5% 就走。粘性应该来自"在你的远程服务器上跑得好"，那是我们唯一擅长的东西。
- **替代方案的成本是负的**：BYOK 意味着用户自己已经付过钱了，我们不需要再收一次钱来证明这个东西值钱。

配套的诚实说法：一键配置模板只写**端点与模型名**，不代管 key；key 落在 `auth.json`（pi 既有机制），不进我们的任何服务器。

## 已有的逃生阀

- 用户想要便宜渠道：模板里给国内合规渠道 + 自定义端点，让他自己选。
- 用户想给团队统一发 key：这是**团队的运维问题**，我们用"配置模板 + 远程同步"帮助分发，不接管流量。
- 我们想变现：付费点是**远程/团队/便利**（远程会话管理、多人共享远程主机配置、团队技能包），与 API 成本无关。
